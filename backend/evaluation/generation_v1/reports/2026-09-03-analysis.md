# 2026-09-03 微调模型固定证据评测

## 结论

当前微调模型可用于带人工复核的演示，但结构化输出和证据忠实度仍不稳定。8 个合成案例中，5 个通过项目输出契约，3 个被拒绝；**62.5% 是字段与引用校验通过率，不是业务正确率。**没有基础模型对照，不能据此证明微调带来提升。

原始报告：[2026-09-03-pcb-qwen-lora.json](2026-09-03-pcb-qwen-lora.json)。失败和第一次尝试均保留。本文件是助手对输出的初步文本审阅，不是领域专家验收，human_review 分数仍为 null。

## 实际执行

- 模型：pcb-qwen-lora；自部署 openai_compatible。
- 8 题顺序执行，共收到 10 次 HTTP 响应，包含 2 次 JSON 语法纠正。
- 每题墙钟时间中位数：4.04185 秒；最近秩 p95：6.9589 秒（8 题时就是最大值）。
- 所有云端响应均为 HTTP 200，但只有 5 题通过项目契约。
- 不访问数据库，不进行检索或规则兜底；固定证据及生成器源码 SHA-256 保存在原始报告。
- 样本为新编写的合成资料，训练重叠情况未知；单轮 8 题不能作为稳定性、生产容量或质量基准。

## 后续改进顺序

1. 检查训练样本的 JSON 语法、字段完整性及引用规则；重点排查中文引号、漏字段和固定化的工具调用措辞。
2. 检查训练/验证集之间的重复、提示模板和 assistant-only 标签边界。当前还没有读取私有训练集，不对数据成因下定论。
3. 扩充证据不足、证据冲突、无工具条件和引用忠实度样本，并建立人工标注评测集。
4. 使用同一评测集和推理设置跑无 LoRA 基础模型对照，再决定是否重训。保持原失败报告，使用新版本数据集和新报告文件。
5. 不通过删除失败题、补造引用或替换成规则输出提高所谓模型通过率。
