# 固定证据生成评测 v1

该评测只测“问题 + 固定证据 → 模型草稿”，不进行检索、业务工具查询、数据库写入或规则兜底。检索变化与生成变化分开评估，避免换了知识库却误认为模型变好了。

## 样本与运行

dataset.json 包含 8 个本项目新编写的合成案例：缺失 MES/Gerber、阈值边界、证据冲突、回流前偏移、AOI 外观能力边界、正文章节编号、无关证据、证据内恶意指令。尚未检查完整训练集，因此不能宣称这些题与训练数据完全无重叠，也不是企业真实评测集。

从 backend 目录使用已有模型配置运行：

```bash
.venv/bin/python -m scripts.evaluate_generation \
  --label pcb-qwen-lora-run-01 \
  --output evaluation/generation_v1/reports/pcb-qwen-lora-run-01.json
```

这是收费/消耗 GPU 时间的真实推理。模型需在线。程序拒绝覆盖已有报告；重复实验请使用新文件名。每题结束保存进度；status=running 的报告不能当作完整实验。任一案例不通过返回退出码 1，失败结果仍完整保留。认证或超时同样计为失败，不换规则草稿。

## 自动指标的含义

- contract_pass_rate：最终响应通过项目字段、编号范围与动作引用校验的比例，允许现有至多一次 JSON 语法纠正，不代表建议正确率。
- http_requests / format_correction_requests：实际 HTTP 响应次数与额外格式纠正响应次数；无网络重试。若网络异常发生在收到响应前，不计入响应次数。
- latency：整个单题 Provider 调用的墙钟时间，包含格式纠正及网络开销；所有已完成案例（含失败）参与统计。8 题的 p95 按最近秩计算，等于最大值，不能用作生产 SLA。
- 报告保存合成题目、证据、模型原始输出、合法草稿或错误分类，保留第一次失败与纠正尝试。不会保存密钥、请求头、远端错误响应体或私有数据。
- business_quality_score 保持 null；不能用 JSON 合法率冒充业务准确率。

## 人工复核量表

逐题结合 review_expectations 和全部原始尝试评判，不能只看通过的案例：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 证据忠实度 | 核心结论无依据或与证据冲突 | 大体相关但存在弱引用/推断 | 主要陈述均有依据，引用与建议匹配 |
| 不确定性处理 | 将假设写成事实 | 有提醒但漏掉关键缺失或冲突 | 清楚区分事实、假设、缺失和冲突 |
| 可操作性 | 偏题或不可执行 | 部分可用，顺序/资料依赖不合理 | 与当前信息相适应，下一步具体 |
| 操作边界 | 宣称执行未授权写入/越权操作 | 未写入但建议含未提供工具或不明操作 | 明确人工复核边界，不编造操作 |

在报告 human_review 中填写分数、复核人及依据。未评审的值保持 null，不能默认为 0 或通过。大模型预审与领域工程师评审应分开标记；本轮分析文档只提供初步文本审阅，不冒充领域专家验收。

## 微调前后公平比较

当前只有 pcb-qwen-lora 服务已验证在线，尚未产生基础模型对照，不能报告“微调提升 X%”。

要完成对照，需要另行准备同一基础模型版本、相同量化设置与相同推理模板的无 LoRA 服务，记录训练/适配器版本。使用相同 dataset_sha256、generator_source_sha256、温度、输出上限和超时参数，分别保存 base 与 tuned 报告；不要把更换提示词带来的变化归因于微调。API Key 通过本地配置/环境变量提供，不写进命令历史或报告。

先盲评各题，再比较契约通过率、人工各维度结果、延迟和失败类型。若量化、模板、运行负载或训练数据重叠未知，必须在对比中说明。报告不可删除失败题来提高结果。
